# Problem Solving

这是一个按需调用的思考工具箱，不是所有任务的固定前置流程。先判断用户当前最需要哪一个动作，再选择一个最小必要方法。简单、明确、可以直接执行的任务直接执行。

## 路由

- 用户说不清自己真正想解决什么：使用“苏格拉底式提问”。
- 用户不理解陌生概念：使用“双层解释法”。
- 用户想学习一个作品、产品或方案：使用“反向拆解”。
- 用户想系统了解陌生领域：使用“横纵分析法”。
- 用户怀疑一条说法、观点或方案：使用“事实核查”。
- 问题横跨多个专业领域：使用“专家会诊”。
- 方案已经被补丁和路径依赖拖复杂：使用“第一性原理”。
- 本行业缺少现成解法：使用“跨领域借解”。
- 两个或多个选项都合理、难以选择：使用“双向钢人论证”。
- 继续讨论不会带来新信息：使用“最小实验”。
- 用户想理解自己的优势：使用“挖掘隐藏天赋”。
- 用户想探索未来方向：使用“人生设计术”。

## 全局约束

- 一次只启用一个主方法；只有任务确实跨阶段时才组合方法，并说明组合原因。
- 先识别目标、现实约束和完成标准；不要把用户的原始表述当成已经验证的目标。
- 需要追问时，优先提出一个最可能改变结论或行动的关键问题；不要无限追问。若信息足够，直接继续。
- 需要比较时，公平呈现正反两边的最强版本，不制造稻草人，也不为了平衡而假装证据相等。
- 不把模型的推测写成事实；事实核查要区分事实、推断、观点和未知，并给出可追溯依据或明确标注未核实。
- 输出面向行动：结论、关键理由、主要不确定性和下一步行动应比过程描述更突出。
- 不要求或展示冗长的隐藏思维过程；只给足以复核结论的摘要、证据和判断依据。
- 完成核心目标后停止，不自动扩展成全面研究、重构、额外课程或完整人生规划。

## 参考模板

需要完整可复制模板时，读取 references/prompt-templates.md，只读取当前方法对应的章节。模板中的方括号内容替换为用户自己的信息。

## 推荐输出形状

根据任务取舍以下字段，不必全部输出：

1. 我理解的目标
2. 关键假设或缺失信息
3. 分析结果或选项比较
4. 结论与置信度
5. 下一步行动或最小实验

## 停止条件

- 问题已经足够清楚，可以执行或判断；
- 关键变量已经识别，继续列举因素不会改变结论；
- 最小实验已经定义，下一步应由现实反馈而不是继续聊天决定；
- 用户已得到明确结论和行动，不再为了“更完整”追加流程。
