# Known Pitfalls (avoid repeating them)

> `SKILL.md` no longer inlines these -- collected here. Each entry maps to an Iron Rule; check here first on a matching symptom.

- **ALL `references/x64dbg/*/SKILL.md` declare their `allowed-tools` (and bodies) under the `mcp__x64dbg__*` prefix, which may not match the x64dbg MCP actually connected.** The MCP server name is set by each user's own MCP config: one case registered it as `mcp__x64dbg-mcp__*` with differently-named commands (`debug_step_into`/`debug_step_over`/`debug_get_state` vs `step_into`/`step_over`/`get_debugger_status`). Note `allowed-tools` is an auto-approval allowlist, not a gate -- a prefix mismatch doesn't make the connected tools unavailable, it just makes each call prompt for permission. So: don't hardcode `x64dbg-mcp` into the files (that breaks setups where the server IS named `x64dbg`); instead verify the live prefix per Rule 1 and use whatever is actually connected. Affects all x64dbg sub-skills (decompile/find-oep/shellcode-analyzer/state-snapshot/tracealyzer/vuln-hunter/yara-sigs). If the step/trace commands are missing entirely, fall back to Frida trace (Rule 14).

- **MCP (x64dbg/IDA) intermittently returns "not found"/empty/"stopped" -> it's usually target STATE, not a dead MCP; don't thrash.** Confirmed causes this session: (a) the debuggee exited/relaunched, so `module_get`/`get_state` legitimately report gone -- re-query after the user reopens; (b) blocked in a syscall (getchar/recv) reads as "running" and `pause` fails -- set a breakpoint on an outside API (`kernel32.Sleep`) and let it hit instead; (c) ASLR rebased the module every launch -- never hardcode absolute addrs across sessions, resolve by export/RVA each run. Probe liveness with a cheap read (`list_instances`/`module_get_main`) before concluding the MCP is down; only then ask the user to reconnect. Every MCP-driven step needs a no-MCP manual equivalent (Scylla GUI dump, manual bp) so one flaky call never stalls the whole flow.

- **Manually single-stepping + `step_out` stack-walking fails structurally on a "fake call stack"** (forged return address pushed + jmp instead of call) -- not operator error, retrying won't help. See Rule 14.

- **.NET/native HttpClient caches proxy settings at startup -> target launched before the proxy starts never routes through Reqable, capture stays sparse all session (defect 3)**: real case -- second login hit "cannot connect to authorization server" because .NET cached a "no proxy" `IWebProxy` at construction when the target started before the system proxy was on; enabling the proxy afterward did nothing. **Fix: start Reqable + system proxy first, then have user open target; switching proxy mid-session needs a target restart.** Hard precondition for .NET/native-desktop targets -- Stage 2's "user opens target" step must confirm proxy readiness first. Signal: per-process capture filter shows almost nothing and the expected auth request is missing -- suspect timing before "not going through network."

- **"App crashes for no reason / bounces to login" in a web thin-client -- check these two before assuming crash or strict auth check**:
  - **(1) Response interceptor's `401 -> clear token -> redirect to login`**: common SPA pattern -- a mount-time call using a fake token gets 401'd by the real server, global interceptor clears token and redirects, **looks exactly like a crash** (see Stage 3's "enumerate first, then forge"). Locate: capture for a 401 right before exit; after deobfuscating frontend, search `interceptors.response`/`401`/`logout`.
  - **(2) Version/forced-update gate** (cheatsheet's Gate-type list): `current version < minimum -> forced update -> exit` also looks like a launch crash. Locate: capture for `/get_latest`, `/version`, or `forceUpdate`.
  - **Order**: last responses before exit (401? forced update?) -> frontend interceptor logic -> only then debug an actual crash.

- **Any dialog popup (including one you triggered) freezes the Qt/GUI modal event loop -- Frida hooks never fire**: hit >=3 times in one run, only a manual restart fixed it -- biggest time sink observed. Target is frozen, not a bad hook. **Before injecting, read-only check no modal is open (Rule 17)**; if a prior injection triggered an error dialog, close it/restart target first.

- **Blind-calling an unknown Cython/builtin to probe param count might execute, not error**: real case -- blind-calling `_set_auth_compromised` with 0 args flipped a live circuit-breaker flag False->True. "Missing param throws, errors are safe" doesn't hold for compiled builtins -- grade by name first; don't blind-call action-prefixed names (`set_/generate_/refresh_/update_/reset_`) just to learn signature (Rule 18).

- **Guessing a backend field name from a frontend variable name -> wrong forged structure, baffling frontend message**: real case -- guessed field from frontend var `lineId`; forged response left frontend stuck on "please select a line first," misdiagnosed as a binding bug for 2 repackage-restart rounds. Get a real response first to build a field dictionary; structure must be an exact copy with only values swapped (Rule 19).

- **Guessing the encryption library incrementally -> request/response used different libraries, extra repackage round needed**: real case -- only `crypto-js` hooked at first, but response decryption actually used Node's native `crypto`, needing an extra round. Once app-layer encryption is confirmed, hook every candidate library at once (Rule 20).

- **Asking the user to "log in once with the correct password" for a success sample violates the red-team zero-credentials stance**: real case -- corrected on the spot. A red team has no correct password/license key -- any step depending on "get one correct login/activation first" is wrong. Right approach: trigger the flow with wrong/empty/forged input, observe the refusal, work backward; even a needed real-server sample is captured under **your own wrong input**, never borrowed credentials (Rule 11).

- **Process not fully exiting during repackaging -> silently corrupted package, exit code still 0**: real case -- a locked `.node` file left asar writing an 8MB corrupted package with a normal exit code, nearly shipped. Zero tolerance for the process not fully exiting before packaging + mandatory integrity check after -- don't trust exit code (Rule 21). For Electron, check the integrity fuse first -- if enabled, use a Frida runtime hook instead of repackaging.

- **Treating "script loaded once in an instantly-exiting process" as "injection channel works" -> false positive while the real channel was blocked**: `NODE_OPTIONS --require` logging one line in a GUI-less, instantly-exiting process falsely confirmed the channel, while the target was actually blocked by a fuse/anti-injection/self-relaunch when fully running. Only count it working with real hook evidence while fully running -- instant-exit, no-GUI, or single-instance-kicked never counts (Rule 23).

- **Retrying the same injection channel repeatedly with zero evidence instead of switching**: real case -- NODE_OPTIONS tried ~5 times with zero evidence (changing cmd, ps1, approach). 2 consecutive zero-evidence attempts means the channel is structurally dead -- switch to an attach-type approach (Frida/--inspect) or render layer/Electron-as-Node, no 3rd attempt of the same kind (Rule 23).

- **Rewriting the launcher repeatedly to guess "the env var isn't getting through" instead of landing a diagnostic first**: write the variable's actual value to a diagnostic file before launching, distinguishing "never set" / "set but not loaded" / "stripped by relaunch" in one pass -- don't guess by rewriting (Rule 23).

- **Chinese text in a generated `.cmd` -> crashes on double-click (GBK console can't parse it)**: real case -- Chinese comments/echo crashed the launcher repeatedly. Any `.cmd`/`.bat` for the user must be pure ASCII with English prompts; a target's Chinese name may only be passed to PowerShell as a quoted string (Rule 24).

- **A `.ps1` containing Chinese saved as UTF-8 *without BOM* -> Windows PowerShell 5.1 reads it as GBK -> phantom "Missing closing '}'" parse errors and refuses to run**: real case -- rewrote `netcheck.ps1` with Chinese comments/strings; the Write tool saved UTF-8 no-BOM, and PS 5.1 (which defaults to the system ANSI/GBK codepage for BOM-less files) misread the multi-byte Chinese trailing bytes, swallowing quotes/braces -- the parser reported missing-`}`/unexpected-`)` at lines that were structurally fine. The code was correct; only the encoding was wrong. **Fix: any `.ps1` that contains non-ASCII must be saved as UTF-8 *with BOM* (`EF BB BF`)** -- the repo's working scripts (e.g. `scan.ps1`) already carry a BOM. Detection: first 3 bytes; if not `EF BB BF` and the file has Chinese, re-save with `[System.Text.UTF8Encoding]::new($true)`. Verify with `[Parser]::ParseFile` (0 errors) + a live run, not just a visual read (extends Rule 24 beyond `.cmd`/`.bat` to `.ps1`).

- **Hand-writing a global `http.request` redirect closure that forgets to call the saved original -> redirects to itself, infinite retry loop**: real case -- closure called the reassigned global instead of the pre-reassignment original, looking like endless target reconnecting (actually harness recursing on itself). Use `nock` instead (tool-registry Sec.5.8, `templates/electron-node-harness.js`) -- avoids this whole class of pitfall.

- **Hand-writing a fake `IncomingMessage`/`ClientRequest` via `EventEmitter` to mock an HTTP response is incompatible with axios's http adapter**: real case -- the mock was missing properties axios reads internally, threw `Cannot read properties of undefined (reading 'includes')`, took a long investigation to confirm the mock itself was the problem. `nock` doesn't have this issue (built for axios/fetch compatibility) -- don't hand-build mocks or an ad hoc `http.createServer`.

- **Hand-writing a `Module._load` interceptor + `Proxy` stub for `require('electron')` -- one missed property (undefined called as a function) forces a full redo**: real case -- rewritten several times as the target kept touching unexpected electron APIs. Use `proxyquire` to declaratively replace modules instead (tool-registry Sec.5.8) -- clearer missing-API errors.

- **Testing multiple independent candidates (keys/response formats/gate locations) one at a time via edit-and-rerun instead of batch testing**: real case -- `drive_login5.js` tested 5 response formats by changing `process.env.FMT` and rerunning each time -- 5 full restart rounds, 4 pure avoidable serialization cost. Batch-test independent sub-hypotheses in a loop in one pass (Rule 25) -- keep only genuinely GUI/user-action steps serial.

- **Mistaking Nuitka/Go/mypyc for "unpack -> de-bytecode" targets -> circling for bytecode that doesn't exist**: Nuitka/.NET-AOT/Go/mypyc-Cython are natively compiled, no bytecode -- need native RE + symbol recovery instead. After checking for packers in Stage 1, route through `references/triage-router.md` before deciding -- a present `pythonXX.dll` alone doesn't mean "interpreter packaging" (Rule 15).

- **Assuming "an MITM proxy mints certs from the request hostname" -> tool actually copied the upstream real cert's SAN**: real case -- minted cert's issuer was the proxy's own CA (decryption confirmed) but SAN was the upstream cert's domain, not the CONNECT/SNI hostname. A single `openssl s_client -proxy <host>:<port> -servername <target>` would've confirmed this in seconds; instead 3 rounds of config changes happened first. Test any MITM/proxy tool's cert-minting rule with a real request before relying on it (extends Rule 19).

- **Same anomaly recurring, every response is "change config -> have user restart the full GUI target" -> high-latency loop for a cheaply-falsifiable hypothesis**: same error recurred 3 rounds straight, each needing a manual restart, when the real root cause (cert SAN rule above) was verifiable in seconds via a standalone openssl command. Same symptom getting the same heavyweight response twice must trigger a switch to a minimal independent repro (extends Rule 14) -- especially costly with a slow-starting GUI target.

- **Multi-value fields (pipe-delimited domain lists etc.) in a JVM argfile/command-line arg -- cmd/shell escaping can silently swallow the delimiter with no error**: `-Dhttp.nonProxyHosts=a|b|c` appeared swallowed under cmd's `^` continuation + quoting; switching to a Java argfile (`@file`, one param per line, not shell-parsed) confirmed it took effect. "Changed a parameter, no error, but no visible change" -> suspect it never reached the process; confirm with a minimal check (`-version` or printing the received value) (extends Rule 24).

- **Packaging/compiling with only the "main class" listed, missing compiler-generated auxiliary classes (e.g. Java anonymous inner class `Outer$1.class`)** -> looks successful (compiles, exits 0), fails at runtime with "class/symbol not found." Specific case of Rule 21's mandatory post-package integrity check -- enumerate **every** file actually produced in the compiled-output directory (not a guessed list) and confirm the packaging input list matches it.

- **"App enters the GUI then instantly exits" mistaken for a DATA gate -> forging an API return/buffer in an endless guessing loop**: real time-sink this session -- treated the launcher's `os._exit()` (fired by a PIC machine-code/integrity check) as "some cloud API's return value/out_buf is wrong," then brute-forced a proxy DLL's `SP_CloudComputing` ret (0 vs 1) and out_buf contents across ~9 rebuilds (v3-v11), each a full rebuild+relaunch. All wrong: the real gate was a **self-`os._exit`**, not bad data. **Correct order on "enters then exits": (1) FIRST classify crash vs deliberate-exit** -- attach faulthandler / hook `os._exit`+`ExitProcess`+`TerminateProcess` and read the exit stack; (2) deliberate exit = an **auth exit-gate** (commonly a PIC/machine-code/integrity check like `sp_PIC_Func_*`/`BuildPack_*` calling `SP_GetCpuid`, or a version/forced-update gate), so **intercept the exit function and let it continue**, then补 whatever the interrupted init skipped (Qt: main-thread QTimer re-run `addSubInterface`/`splash.finish()`); (3) only after ruling those out, debug an actual crash. Never assume "a return value/buffer is wrong" and grind-forge it before you've read the exit stack.

- **Declaring a "cloud-compute / server-side-data DEAD END" without proof, on a shell whose name sounds server-authoritative**: real miss -- concluded `SP_CloudComputing`'s `out_buf` "needs real server data, locally unforgeable, dead end" and nearly stopped. Wrong: the actual authorization was a **client-side boolean gate** (`SP_CloudLogin` returns 0/1, forceable), and the real blocker was elsewhere (an `os._exit` exit-gate). "It's a cloud/云计算 function" does NOT prove the verdict is server-side -- enumerate EVERY gate's real mechanism first (Rule 15's defense-in-depth), and don't let a scary name trigger a premature "unbeatable" verdict. If the user says "I got in before with a hook," believe the path exists and keep localizing, don't re-assert the dead end.

- **Overlooking that a functional backend often ships its own venv and runs standalone -- the cleanest bypass, missed entirely**: real miss -- burned the whole session attacking the auth SDK DLL, never noticing `digital/server.py` runs directly via its bundled `heyi\python.exe` (`cd digital && heyi\python.exe server.py` -> local Flask on :5080, **zero auth, zero account**). For any "launcher + functional backend" app (esp. Python-packaged), **FIRST probe whether the backend runs detached from the auth shell** -- own python.exe/venv, a localhost service port, config with a server_port -- before diving into the protected launcher. The auth shell often only guards the *launcher*, not the *功能*.

- **Reflex to reach for a heavyweight tool (Intel Pin/UnSafengine64) on a hard shell without a version smoke-test -> guaranteed crash + wasted integration**: real dead-end (twice: nearly re-walked it) -- UnSafengine64 is validated only on **Pin 3.18 + Safengine 2.3-2.4**; the only downloadable Pin now is **3.31**, and SE's anti-DBI crashes Pin 3.31 (`UPC Dispatcher: Unhandled internal exception RECEIVED_ACCESS_FAULT`) before reaching OEP. Per Rule 3, a 5-min version-compat smoke test kills this before compiling+adapting 4 vcxproj spots. **For SE/SProtect, the reliable unpack is ScyllaHide+x64dbg dump (tool-registry Sec.0.9 strong-technique note), NOT Pin.**

- **Many blind hook/patch rounds re-guessing values or names = structurally stuck; stop guessing and get GROUND TRUTH.** Real time-sink: dozens of rounds re-guessing a function's return value and re-guessing GUI attribute names (guessed `home_interface`; the real one was `homeInterface`) -- each a full restart. The tell you're stuck: **you keep editing your OWN artifact (the same patch/proxy) and feeding new guesses**. Stop-loss (Rule 14/23): the fix is never another guess -- get ground truth cheaply, three ways: (1) **introspect the live object** for REAL attribute/method names (`dir()`/reflection/CDP; never guess casing/naming); (2) **read the contract** (unpack+static, or observe the real value once) instead of brute-forcing candidates; (3) **search how others hook/analyze this runtime/framework class** (Rule 3 applies to the hook route too, whatever the stack -- query `<runtime-or-framework> <symptom-or-API> hook/patch`). Guessing has no convergence; one ground-truth read (or one on-point search hit) collapses the search space. Any embedded `pythonXX.dll` exports `PyGILState_Ensure`/`PyRun_SimpleString`/`PyGILState_Release`; from a proxy DLL loaded into the process, or via Frida (`NativeFunction` on those exports), you can `PyRun_SimpleString(<arbitrary python>)` on the target's own runtime -- introspect `sys.modules`/class `__dict__`/live-object attrs, and **monkeypatch the auth methods directly** (these edits are detach-persistent). This beats static de-compilation when the app is Nuitka (no bytecode) or the logic is buried. Caveat: same-module/intra-class calls Nuitka compiles to direct calls don't go through the module dict -- **patch the name in the CALLER's namespace** (the module that imported it), not only where it's defined; a background thread re-applying the patch handles lazily-imported modules.

- **Keep the injected patch MINIMAL and single-purpose; don't pile probes + replacements into one blob.** Real time-sink: one bloated in-process script forced login + replaced a decrypt-fed function + swallowed init exceptions all at once, and the replacements fought each other, masking which change mattered. Iterate one hypothesis per run; load patch logic from an EXTERNAL file the injector `exec`s (edit the file, re-trigger -- no recompiling the injector DLL).

- **Read the TARGET'S OWN crash log before dumping/hooking/guessing.** Real breakthrough: a `JSONDecodeError` then `IndexError` in the app's own `%APPDATA%/<product>/log` gave exact `file:line:exception` for free while rounds were spent guessing. **Step 0 of any crash/exit/stuck-window symptom: find + tail the target's own log** (`<dir>/log/`, `%APPDATA%`, `%LOCALAPPDATA%`, sibling `*.log`; managed runtimes write full tracebacks). Full decision tree: `crash-exit-handling.md`.

- **Exit-interception order matters; native-first freezes the UI.** Real dead-end: hooked `kernel32!ExitProcess` + spun a message-pump/`Sleep` loop on the hit -> the hit was on the **main (event-loop) thread** -> "Not Responding" + Windows kill dialog. Fix: intercept at the **highest layer first** (runtime `os._exit`/`sys.exit`/`Environment.Exit`/`process.exit` -> CRT `_exit` -> native `ExitProcess`/`RtlExitUserProcess` last); on the main thread **only no-op-return, never sleep/loop/block**. `crash-exit-handling.md`.

- **"Blocked the exit" != "entered the UI" -- exit is not the gate.** After no-op'ing the self-exit the process lived but stayed on the splash: mount was gated by a *positive* "check passed" branch (`if ok: build_ui() else: exit()`), so no-op'ing exit fell through the `else`. Must **enumerate the mount fn and call it from the runtime on the UI/main thread** -- `crash-exit-handling.md` + `runtime-injection-hooking.md` §5.

- **A fake/proxy SDK DLL must return data in the caller's EXACT expected shape, not just a success code.** Crash chain: a stub returned `1` but left the **caller-provided output buffer** empty/garbage -> the app's `json.loads("")` / `list[2]` blew up downstream. Many SDK exports **write into a caller buffer (`create_string_buffer`/out-pointer)**, not return a pointer -- fill it and match the exact parse format (valid JSON, real keys). **First choice to learn the shape: proxy-forward to the REAL DLL and log its buffer output** (ground truth: real server JSON + real call sequence) before faking. `auth-bypass-cheatsheet.md`.

- **Non-ASCII (e.g. Chinese) paths are a whole-toolchain encoding minefield -- use an ASCII-only scratch dir.** Real time-sinks: MSVC `.bat` with a UTF-8 BOM breaks `@echo off`; MSYS/git-bash turns a bare `/c` arg into `C:\` (use `MSYS_NO_PATHCONV=1` or `//c`); bash/Python escapes choke on `\U`(sers)/`\6`; `PyRun_SimpleString` parses source as UTF-8 so a Chinese path's GBK bytes -> `SyntaxError` (whole injection silently fails); GBK console can't print emoji (`UnicodeEncodeError` aborts the script); `frida.spawn` fails on a non-ASCII exe path. **Rule 24 extended: put ALL scripts/logs/build-output/injected-source in an ASCII-only dir (`C:\Users\<user>\`), keep injected source pure ASCII (`\uXXXX`-escape CJK), copy artifacts back to the target dir.**

- **Clean the target's process tree before replacing its DLL/files, and expect to need elevation.** Replacing a loaded DLL fails ("being used by another process") while the target or a child (e.g. a spawned `server.py`) holds it; worse, a **requireAdministrator-manifest target runs at higher integrity than a non-elevated shell** so `taskkill`/`Stop-Process` return access-denied. **Fixed pre-deploy step of every edit->redeploy->retest loop: enumerate + kill the whole tree (`taskkill /F /T`), elevate if denied (`Start-Process -Verb RunAs`), confirm gone, then copy.**

- **`QTimer.singleShot(0, fn)` created on an injected/Frida thread never fires** (timer binds to a thread with no Qt event loop). Run GUI work on the main thread from an injected thread via a `QObject`+`Signal`, `moveToThread(app.thread())`, `connect(slot, QueuedConnection)`, then `emit`. Per-framework equivalents: WinForms `Control.BeginInvoke`, WPF `Dispatcher.Invoke`, GTK `idle_add`. `runtime-injection-hooking.md` §5.
