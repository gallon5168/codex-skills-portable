# 崩溃 / 自杀退出 / 卡界面 处理(通用软件)

> **何时读**:目标进程在初始化或校验后**自行退出(exit/abort/TerminateProcess)、闪退、或窗口卡住不动("未响应")**;或你在"拦住退出但进不去主界面"上打转。适用任何 GUI/CLI 软件,不限语言/打包方式。
> 核心认知:**退出是"失败后的动作",不是"门"本身**。多数软件的主功能挂载被"校验通过"**正向门控**——拦住退出只让进程不死,不等于进入功能。

## 第 0 步:先读目标自己的崩溃日志(最高优先,别先猜)

崩溃/闪退的**决定性证据常在目标自己的日志**里,免费给出"文件:行号:异常类型"。动手 dump/hook/猜之前:
- 找并 tail 目标的 log:常见位置 `<目标目录>/log/`、`%APPDATA%/<产品>/`、`%LOCALAPPDATA%`、目标同目录 `*.log`、`logs/`;运行后按修改时间取最新。
- 有 Python/托管运行时的目标,未捕获异常常被其自带 logger 写成完整 traceback → 直接给出崩溃函数+行号+异常。
- 无自带日志 → 控制台运行(CLI 直接看 stderr;GUI 用 `<exe> 2>err.txt` 或系统事件查看器/WER `%LOCALAPPDATA%\CrashDumps`)。
- **一句话规则**:目标已经告诉你它为什么死,先去读,别用逆向猜它已经打印出来的东西。

## 退出拦截决策树(顺序不能反)

目标调退出让进程终止时,按**从高层到底层**依次尝试拦截——高层拦截副作用小、不易冻线程:

1. **解释层 / 运行时 API 优先**(最安全):把语言级退出函数变 no-op。
   - Python:`os._exit`/`sys.exit`/`atexit`/`builtins.exit|quit` 置为空函数。
   - .NET:`Environment.Exit`/`Application.Exit`;JVM:`Runtime.exit`/`System.exit`;Node:`process.exit`。
   - 手段:进程内注入 / 运行时 hook(见 `frida-win`)。
2. **运行时库层**:CRT `_exit`/`exit`、`abort`。
3. **native 系统调用兜底**:`kernel32!ExitProcess` / `ntdll!RtlExitUserProcess` / `TerminateProcess`。**只在 1、2 拦不住时才用**,且见下条红线。

**为什么顺序不能反**:直接 native 拦 `ExitProcess` 常在**主线程**命中,而主线程 = GUI 事件循环线程。见下。

## 红线:绝不冻结主线程(否则"未响应")

GUI 程序主线程跑事件循环。任何在主线程上的 **sleep / 死循环 / 同步阻塞等待** 都让窗口"未响应",系统弹关闭对话框。
- 拦截点若落在主线程:**只能快速返回(no-op return)**,不能 `Sleep`/`while(1)`/`WaitForSingleObject`。
- 万不得已要在主线程"保活",跑 **消息泵**(`PeekMessage/DispatchMessage` 循环)而非死睡——但这仍是下策,首选高层 no-op 让线程自然返回。
- 真实教训:native 拦 `ExitProcess`+主线程死循环 → 立刻"未响应";改成解释层 `os._exit` no-op(线程正常返回)后正常。

## 退出门 ≠ 挂载门(拦住退出仍进不去,看这里)

拦掉退出后进程不死、但**主界面没出来**,几乎总是因为:
- 主界面挂载被"校验成功"这个**正向条件**门控:`if check_ok: build_ui()  else: exit()`。你把 exit no-op 了,`else` 分支直接返回,`build_ui()` 从没被调。
- **对策**:枚举"挂载函数"(建主窗/切界面/关闭启动图 splash 的调用),在拦住退出后**从运行时主动补调它**(见 `frida-win` 的"运行时补挂载")。GUI 挂载必须在 **UI 主线程**执行(跨线程直接操作控件会崩)。
- 补挂载前**先 introspect 活对象拿真实属性/方法名**(窗口实例的 interface/splash/navigation 成员),别猜名字。

## 多道门:一次性枚举,别逐个撞

防御纵深是常态。**先通读授权/初始化胶水层,把所有门列出来**,别翻一道撞下一道:
- 典型门序列:输入校验 → 数据拉取(返回被解析,如 JSON) → 完整性/反篡改自检 → 二次校验(心跳/机器码) → 挂载期再校验。
- 翻掉一道后,立即用 tracer(未捕获异常 hook / 日志 / 单步)找**下一个终止点**,直到真功能跑起来。
- 置信度:`[gate]`翻转 < `[alive]`存活 < `[OK]`用户亲见功能真跑。只有 `[OK]` 算数。

## 收尾

每定位一道门/一次拦截结果,立即按 Rule 7 写回 attempts.md + 更新锚点;拦截手段被证明无效的,`[X]`+证据留痕,别重试同一条。
